JEV 的 Choice、Noul、Score 分别做什么？

形式适合的问题示例
Choice在明确候选选项中选择工单应分到售前、技术还是账单队列？
Noul对是与否的判断给出概率这条请求是否需要人工复核？
Score按照有序标准进行评分这件事情的紧急程度属于哪一档？

体验页面会展示示例请求、问题定义与原始响应。Choice 的选项使用明确的对象定义，Score 使用从低到高的有序标准；实际字段和返回值应结合当前接口文档核对。

如何在线体验 JEV 1.13？

  1. 打开 Playground，选择一个客服、运营或路由示例。
  2. 查看背景与问题定义，把示例内容改成不包含隐私的测试输入。
  3. 预览请求，确认模型、接口和选项符合任务要求。
  4. 需要实时运行时填写自己的 CrazyRouter API Key；提交会产生真实 API 请求，可能计费。
  5. 检查结构化答案、概率分布和原始 JSON，再决定是否用于你的流程。

客服分流和 Agent 路由可以怎样设计？

先定义互斥、清晰的队列或工具选项，再说明每个选项的触发条件。例如，“账单”处理充值与扣费，“技术”处理接口错误，“人工复核”接收信息不足或多类混合的问题。不要只给选项名称，却不告诉模型分类边界。

在 Agent 路由中，JEV 的决策结果可以作为后续逻辑的输入，但执行层仍要检查权限、参数和失败回退。涉及付款、删除或外部消息等动作时，不能把概率最高的答案直接当作授权。

置信度高，是否意味着判断一定正确？

不是。页面里的 confidence 描述概率分布的确定程度，并非经过你业务数据校准后的正确率。应使用带标签的样本评估混淆矩阵、误分成本与人工回退比例，然后选择合适的阈值。

JEV 与让聊天模型输出 JSON 有什么不同？

两者都能服务于结构化流程，但任务接口、结果形式和评估方法可能不同。应比较你实际问题上的准确性、稳定性、延迟与成本，而不是仅凭“能返回 JSON”判断是否适合。Playground 展示的是决策用例，并非通用聊天或所有分类任务的质量承诺。

如何从体验接入到应用？

页面提供请求预览和代码示例。确认样例运行正确后，把 API Key 放到服务端环境变量中，添加日志脱敏、超时、错误处理和业务回退。当前浏览器体验只在页面内存中保存密钥，不将其写入本地存储；生产应用通常应通过自己的服务端发起请求。

JEV 在线体验：常见问题

JEV 体验需要登录吗？

可以直接浏览示例和请求结构。实际运行需要可用的 API Key，并可能产生接口费用。

JEV 适合写长文章吗？

这里的 Playground 面向分类、判断、评分与路由。长文本创作属于不同需求，应选择适合生成任务的模型。

可以用 JEV 做内容审核吗？

可以把它作为待评估的分类或辅助决策组件，但应在自己的标注数据上测试，设置人工复核，并避免把模型输出当作唯一安全措施。

为什么要保留人工回退？

输入不完整、分类边界模糊或分布变化都可能导致错误。把低置信度或高风险任务送到人工处理，有助于控制业务误判成本。
